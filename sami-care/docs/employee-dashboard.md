# الموظفون والتقييمات والأداء والورديات

## الاستخدام

- من قائمة الموظفين: مفتاح الحالة يفعّل الموظف أو يوقفه. لا يظهر الموظف الموقوف أو المحظور في اختيار موظف الحجز، وتُرفض محاولة حجز جديدة باستخدام اختيار قديم له.
- متوسط التقييم وعدد التقييمات يظهران في القائمة وفي نموذج تعديل بيانات الموظف. رابط الرسم البياني بجانب الموظف يفتح تقرير أدائه.
- يجمع المتوسط تقييمات موظفي الخدمات المسجلة مع تقييم الحجز وتقييمات الموظفين القديمة. لكل موظف رأي واحد لكل عميل وحجز، بمتوسط تقييم خدماته عند تعددها. التقييم الحديث يأخذ الأولوية على التقييم القديم لنفس الحجز. المتوسط الداخلي يشمل الآراء غير المعتمدة للنشر أيضاً.
- صفحة التقييمات القديمة تحتوي رابطاً واضحاً لتقييمات الموقع الحديثة. صفحة آراء العملاء تعرض تقييم الفرع والخدمات والموظفين وتدعم الاعتماد والحذف بروابط تعمل مع التثبيت داخل مجلد فرعي.
- التقرير يُرشح حسب تاريخ موعد الحجز، ويعرض المكتمل والملغى وعدد الخدمات ودقائق الخدمات المكتملة وقيمة الخدمات والباقات المسجلة كمدفوعة والتحصيل الموثق.

## حساب التحصيل

تحفظ المدفوعات الجديدة في `invoices.collection_details` المبلغ المحصل عبر البوابة والمحفظة، وتفصل عنه قيمة نقاط الولاء. الدفع عند الوصول يسجل العربون فقط. هذه إضافة سجل للتقرير ولا تغير المبالغ أو طرق الدفع.

يوزع التحصيل على الموظفين بنسبة قيمة خدمات وباقات كل موظف إلى قيمة السلة قبل الضريبة والخصومات، بما يشمل عدم نسبة المنتجات والهدايا إلى الموظف. الحساب لا يكرر الفاتورة عند تكرار سجلات محاولة الدفع. المدفوعات القديمة تستخدم سجلات البوابات والعربون المتاحة؛ المدفوعات من المحفظة التي لا يوجد لها سجل توزيع قديم لا يمكن استنتاجها بدقة، ويظهر غياب سجل التحصيل المفصل بدلاً من اعتبار إجمالي السعر تحصيلاً.

## الورديات

من تقرير الموظف يمكن تغيير الوردية وتحديد ثابتة أو تناوب أسبوعي وتاريخ مرجعي. أسبوع المرجع يستخدم الوردية المختارة، ويبدأ الأسبوع يوم الأحد. التناوب يعمل بين ورديتين نشطتين فقط، بخلاف ذلك تستخدم الوردية المحددة. الوردية الموقوفة أو غير المحددة لا تعطي مواعيد حجز. نفس السياسة مستخدمة في مساري أوقات الحجز، وتغيير الوردية لا ينقل الحجوزات القائمة.

تم الحفاظ على سلوك التناوب الحالي للموظفين الموجودين: تفعيل التناوب والمرجع `2026-02-15`. تغيير بيانات الموظف العادي يحفظ إعدادات التناوب، وفتح نموذج التعديل لا يستبدل الفرع أو الوردية باختيارات الجلسة الحالية.

## التطبيق والفحص

1. تثبيت اعتماديات Laravel إن لم تكن موجودة: `composer install` من مجلد `sami-care`.
2. تطبيق الترحيلات: `php artisan migrate`.
3. بناء لوحة التحكم طبقاً لإعدادات Laravel Mix للمشروع (اعتماديات لوحة التحكم مطلوبة).
4. الاختبار المستقل: `php tests/Unit/EmployeeDashboardSmoke.php`.
5. بعد توفر قاعدة البيانات: جرّب إيقاف موظف والتأكد من اختفائه ورفض اختيار سابق له، وإرسال تقييم لحجز مكتمل، وفتح تقرير الموظف، وتجربة وردية ثابتة ثم تناوب أسبوعين ويوم إجازة.

تمت إضافة ترحيلين لهذه المهمة: إعدادات تناوب ورديات الموظف وتفاصيل تحصيل الفاتورة. فحوص التكامل مع Laravel وقاعدة البيانات تتطلب مجلد `vendor` غير الموجود في نسخة العمل الحالية.
