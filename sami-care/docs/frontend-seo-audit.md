# مراجعة SEO وsitemap وrobots

## ما تم ضبطه

- بيانات العنوان والوصف والكلمات المفتاحية تستمر في القراءة من `/api/seo` وإعدادات الداشبورد لكل صفحة ولغة.
- أضيف رابط canonical واحد للعنوان الأساسي دون باراميترات التتبع أو توكنات الحساب والهدايا، مع توحيد aliases مثل `services.html`.
- أضيفت وسوم Open Graph وTwitter، وتتغير مع العنوان والوصف والصفحة واللغة. هذه البيانات مضافة بجافاسكربت؛ برامج المشاركة التي لا تنفذ JavaScript تحتاج عرض بيانات الرأس على الخادم أو prerender على الاستضافة للحصول على معاينة خاصة بكل صفحة.
- الحساب والحجز والإيصال واستلام الهدايا تحمل noindex,follow. الصفحات غير الموجودة تعرض صفحة واضحة مع noindex بدلاً من التحويل الصامت للرئيسية. عند رد SEO API بـ404 تضبط الصفحة noindex، بينما فشل الاتصال العابر يحتفظ بالبيانات الافتراضية.
- تعتمد الصفحات على عرض JavaScript الحالي؛ هذه المراجعة لا تحول التطبيق إلى SSR ولا تثبت الفهرسة الفعلية في محرك البحث. مرجع جوجل: https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics

## خريطة الموقع

`/api/seo-sitemap` في Laravel يولد XML من الصفحات العامة والخدمات النشطة (تصنيفات مسارات `/services/{id}`) والمقالات المنشورة. يستبعد صفحات الحساب والدفع والهدايا الخاصة والخدمة المنزلية الموقوفة. يستخدم `SEO_SITE_URL` مع قيمة افتراضية `https://sami-care.sa`.

في بناء الفرونت يربط `.htaccess` المسار `/sitemap.xml` بـ`sitemap.php` الذي يجلب XML من `https://dashboard.sami-care.sa/api/seo-sitemap` ويتحقق من XML والنطاق. يحتاج Apache وmod_rewrite وPHP مع cURL وSimpleXML على استضافة الفرونت. عند تعذر الاتصال يستخدم ملف sitemap.xml الاحتياطي الموجود بجانبه، والذي يحتوي صفحات عامة ثابتة فقط بدون معرفات خدمات أو مقالات قديمة.

عند استخدام استضافة ملفات ثابتة بدون PHP، تخدم النسخة الاحتياطية فقط؛ يلزم ربط `/sitemap.xml` عبر reverse proxy بمسار Laravel أو توفير توليد الخريطة ضمن آلية النشر لتحديث الروابط الديناميكية. لا يلزم migration جديد.

## robots.txt

نسخة الفرونت تشير لخريطة الموقع في النطاق الرئيسي وتسمح بملفات العرض والـAPI. لا تُحجب الصفحات الخاصة من الزحف حتى يمكن قراءة noindex الخاص بها. نسخة الداشبورد تمنع زحف صفحات الإدارة وتسمح بمسارات API والوسائط العامة التي يحتاجها عرض الفرونت. robots ليس وسيلة لحماية البيانات؛ المصادقة الحالية تبقى مطلوبة.

## التحقق وحدوده

- `php tests/Unit/FrontendSeoSmoke.php`: 16 فحصاً.
- `php tests/Unit/SitemapSmoke.php`: 11 فحصاً.
- `node --test tests/seo-technical.test.cjs` من مجلد الفرونت: فحصا canonical وبيانات المشاركة ومنع الفهرسة مع تأكيدات متعددة.
- `npm run build`: نجح، بما فيه نسخ sitemap.php وrobots.txt و.htaccess إلى dist.
- اختبارات seo.browser.test.cjs تم تخطيها لأن Playwright/خادم الاختبار غير متوفرين.
- تعذر الوصول إلى robots.txt وsitemap.xml للموقع المنشور من أداة التصفح؛ لا يمكن الجزم بصحة إعدادات الاستضافة أو فهرسة Google من فحص المصدر وحده. Laravel غير قابل للتشغيل هنا لغياب vendor.

بعد النشر: افتح robots.txt وsitemap.xml على النطاق الرئيسي، وتأكد أن الخريطة XML وليست HTML وأن المسارات الجديدة تظهر. افحص صفحات عامة وخاصة من Google Search Console، وتأكد من الاستجابة والـcanonical والنسخة المعروضة.
