# إشعارات المتصفح

تضيف الميزة زر تفعيل/إيقاف داخل صندوق إشعارات العميل. بعد الموافقة، يستقبل المتصفح نسخة من الإشعارات الجديدة المسجلة للحساب حتى عندما لا تكون صفحة الموقع مفتوحة. الضغط على الإشعار يفتح صفحة الحساب. لا تُرسل الإشعارات القديمة عند الاشتراك.

## تشغيل السيرفر

1. تثبيت الاعتماديات: `composer install`. ملف القفل الحالي لمكتبة Web Push يحتاج PHP 8.2 أو أحدث. تعثر التنزيل محليًا بسبب رفض المصادقة من GitHub؛ يلزم إكماله قبل التفعيل.
2. تنفيذ `php artisan migrate` لإضافة جدول اشتراكات المتصفحات.
3. تنفيذ `php artisan webpush:keys` مرة واحدة، وحفظ المفتاحين في بيئة السيرفر فقط. لا تغيرهما بعد الاشتراك إلا مع خطة لإعادة اشتراك الأجهزة.
4. ضبط المتغيرات التالية:

```dotenv
WEBPUSH_ENABLED=true
WEBPUSH_PUBLIC_KEY=generated-public-key
WEBPUSH_PRIVATE_KEY=generated-private-key
WEBPUSH_SUBJECT=mailto:your-real-support-address@example.com
WEBPUSH_QUEUE_CONNECTION=webpush
```

5. تحديث كاش الإعدادات وفق إجراءات النشر، وتشغيل عامل دائم تحت مدير عمليات:

```sh
php artisan queue:work webpush --queue=webpush --tries=3 --timeout=120
```

اتصال `webpush` المضاف يستخدم جدول jobs الموجود في المشروع ويضبط `retry_after` على 180 ثانية، أكبر من مهلة العامل. لا تستخدم اتصال sync للإنتاج، حتى لا يؤخر إرسال الإشعارات عمليات الحجز والدفع.

6. بناء ونشر واجهة `front-end/project-sami` باستخدام `npm run build`، بما فيها `sw.js` و`browser-push.js` و`customer-notifications.js`. الموقع يجب أن يعمل على HTTPS. عامل الخدمة الحالي ينتظر إغلاق الصفحات القديمة قبل تنشيط تحديثه لحماية عمليات الدفع المفتوحة.

## السلوك والحماية

- تُنشأ مهمة الإرسال بعد تثبيت معاملة حفظ الإشعار. تحديث حالة القراءة لا يولّد رسالة جديدة.
- الاشتراك مرتبط بالمستخدم المصادق عليه، ويُرفض ربط اشتراك مملوك لحساب آخر. إلغاء الاشتراك من السيرفر مقيد بصاحب الحساب.
- عند الخروج أو تغيير الحساب في الواجهة، يُلغى اشتراك المتصفح. الاشتراك يتجدد عند زيارة الحساب وينتهي بعد 90 يومًا دون تجديد.
- تُقبل فقط عناوين خدمات الدفع المعروفة عبر HTTPS، ولا تُتبع التحويلات عند الإرسال.
- الاشتراكات المنتهية لدى مزود الدفع تُحذف، والمحاولات الفاشلة تُعاد. قد يتكرر التسليم عند إعادة المحاولة؛ يستخدم المتصفح معرّف الإشعار لاستبدال التنبيه نفسه.
- تُرسل الرسائل للأجهزة المشتركة فقط، وتُتجاهل الحسابات الموقوفة والمحظورة والإشعارات المقروءة أو الأقدم من يوم.
- نص الإشعار قد يظهر على شاشة القفل؛ يفضّل تجنب المعلومات الحساسة في قوالب الرسائل.

## متطلبات العميل والتحقق

الموافقة على إذن الإشعارات مطلوبة. على iPhone/iPad يلزم تثبيت الموقع على الشاشة الرئيسية في إصدارات النظام الداعمة ثم تفعيل الإشعارات منه. وصول الإشعار يتأثر بالاتصال وإعدادات الجهاز والمتصفح؛ لا يُضمن وصول فوري إذا كان الجهاز غير متصل أو منع النظام تشغيل المتصفح في الخلفية.

اختبر حسابين مختلفين، رفض الإذن وقبوله وإلغاءه، إغلاق الصفحة، الضغط على الإشعار، تسجيل الخروج، وتحديث الحجز. اختبارات التطبيق: `php vendor/bin/phpunit tests/Feature/BrowserPushTest.php`. لا يغني نجاحها عن اختبار تسليم فعلي على HTTPS بعد تثبيت المكتبة وضبط المفاتيح والعامل.

المراجع: [مكتبة Web Push](https://github.com/web-push-libs/web-push-php)، [إشعارات الويب لدى Apple](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers).
